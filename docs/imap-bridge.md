# Setting up the IMAP bridge

Mail Vibes reads Google and Microsoft 365 mail straight from your browser. Other mailboxes (a
hosting provider's mailbox, Italian PEC, a self-hosted server…) only speak **IMAP** and **SMTP**,
and browsers can't open those connections. The **bridge** solves this: a very small program that
you run for free on your own Cloudflare account. Mail Vibes talks to the bridge, and the bridge
talks to your mail server.

You only need the bridge if you want to add an IMAP mailbox. Google and Microsoft 365 accounts
never go through it.

## What the bridge does, and doesn't do

- It **copies bytes** between Mail Vibes and your mail server. Reading, sending and understanding
  mail all happen in your browser.
- It **stores nothing** and **logs nothing**: no passwords, no mail, no addresses.
- It only accepts connections **with your access key**, **from the Mail Vibes address**, to
  **mail ports** (993, 143, 465, 587, 4190) on **public servers**, and always **encrypted**.
- **Be aware:** the encryption to your mail server ends inside the bridge, so your password and
  your mail pass through the bridge's memory while it relays them. That's why you should run
  **your own** bridge and never use someone else's.

The code is a single file, [`bridge/worker.js`](../bridge/worker.js), short enough to read.

## What you need

- A free Cloudflare account (no credit card is needed for the free plan).
- About 10 minutes.

The free plan allows 100,000 requests a day. Mail Vibes uses one per connection to a mail
server, a few hundred a day at most, even with several accounts.

## Step 1: choose an access key

The access key stops other people from using your bridge. Make it long and random, for example
40 characters generated by your password manager. Save it in your password manager: you'll type
it in Cloudflare (step 3) and in Mail Vibes (step 5).

## Step 2: create the bridge (Cloudflare dashboard)

1. Sign in at [dash.cloudflare.com](https://dash.cloudflare.com) (or create a free account).
2. In the menu on the left, open **Compute** → **Workers & Pages** (the names may differ
   slightly as Cloudflare updates its site).
3. Click **Create** → **Create Worker** (or **Start with Hello World!**).
4. Name it, for example `mail-vibes-bridge`, and click **Deploy**.
5. Click **Edit code**. Delete everything in the editor, then copy the **whole** content of
   [`bridge/worker.js`](../bridge/worker.js) (open it on GitHub, click **Raw**, select all, copy)
   and paste it in.
6. Click **Deploy** (top right).

## Step 3: set the access key and the allowed address

Go back to the Worker's page and open **Settings** → **Variables and Secrets**. Add two entries:

| Type | Name | Value |
| --- | --- | --- |
| **Secret** | `ACCESS_KEY` | the access key from step 1 |
| Text | `ALLOWED_ORIGINS` | `https://camillopatricelli.github.io` |

`ALLOWED_ORIGINS` is the address Mail Vibes is opened from, without any path. If you host
Mail Vibes yourself, put your own address instead. Several addresses can be separated with
commas.

Click **Deploy** (or **Save and deploy**) if Cloudflare asks.

**Turn logs off** (recommended): in **Settings** → **Observability**, make sure **Workers Logs**
is disabled. The bridge never writes logs itself, but Cloudflare can record request details.

## Step 4: copy the bridge's address

On the Worker's page, under **Domains & Routes**, you'll find an address like
`https://mail-vibes-bridge.<your-name>.workers.dev`. Copy it.

Open it in your browser: it should just show `ok`.

## Step 5: connect Mail Vibes

1. In Mail Vibes, open **Settings** → **IMAP bridge**.
2. Paste the address into **Bridge address** and the key into **Access key**.
3. Click **Check bridge**. You should see "The bridge answers and the access key is right."
4. Click **Test a mail server** and enter your mailbox's settings to check that everything works.
   The test reads your Inbox without changing anything.

"Include address and key in the settings file" is off by default: the settings file you export
then won't contain the access key. Turn it on if you want to move the bridge to another device
with the file (and keep the file somewhere safe).

## Alternative: deploy from the command line (Wrangler)

If you're comfortable with a terminal and have [Node.js](https://nodejs.org) installed:

```sh
git clone https://github.com/camillopatricelli/mail-vibes.git
cd mail-vibes/bridge
npx wrangler login
npx wrangler secret put ACCESS_KEY      # paste your access key when asked
npx wrangler deploy
```

`ALLOWED_ORIGINS` is set in [`bridge/wrangler.toml`](../bridge/wrangler.toml); edit it if you host
Mail Vibes yourself. Wrangler prints the bridge's address when it's done.

## Updating the bridge

When Mail Vibes needs a new version of the bridge, the app will tell you. Repeat step 2.5–2.6
(paste the new `worker.js` and deploy) or run `npx wrangler deploy` again. Your access key and
settings are kept.

## Custom domain (advanced)

The public Mail Vibes site can only reach bridges on `workers.dev`, because its security policy
(CSP) must list every address it may connect to. If you build and host Mail Vibes yourself, you
can allow a bridge on your own domain by building with
`VITE_BRIDGE_ORIGINS=wss://bridge.example.com`.

## Troubleshooting

| Message | What to check |
| --- | --- |
| "The bridge can't be reached" | The address (copy it again from step 4), and that `ALLOWED_ORIGINS` contains the exact address Mail Vibes is opened from. |
| "The bridge refused the access key" | The key in Mail Vibes and the `ACCESS_KEY` secret must be identical. |
| "Port not allowed" | Mail servers use 993 (IMAP, SSL/TLS), 143 (IMAP, STARTTLS), 465 (SMTP, SSL/TLS) or 587 (SMTP, STARTTLS). |
| "Encryption is required" / "STARTTLS is not used on this port" | Use SSL/TLS with ports 993 and 465, STARTTLS with 143 and 587. |
| "The server refused the user name or password" | The user name is not always your email address (some providers use a user ID). If your provider offers **app passwords**, use one. |
